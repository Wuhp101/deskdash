# deskdash

A full-screen dashboard for the Wokyis dock's 5" 1280×720 screen: clock and weather, Hyperliquid tickers, and the state of Claude Code and Codex sessions. Read [README.md](README.md) for what it does. This file is for agents changing it. A gitignored `CLAUDE.local.md`, if there is one, adds notes for the machine you are on.

## Commands

- Build: `scripts/build.sh` (Command Line Tools only; no Xcode needed). It runs `swift build -c release`, then assembles and signs `deskdash.app` (ad hoc, or with the stable "deskdash local signing" identity once `scripts/make-signing-identity.sh` has made it, so macOS keeps its privacy permissions across rebuilds) (bundle ID `local.deskdash`) and registers it with LaunchServices. The login service runs `deskdash.app/Contents/MacOS/deskdash`. Never point a service at `.build/release/deskdash`: macOS ties a bare binary's Local Network permission to its build UUID, so every rebuild would cut it off from the purifier.
- See every page: `.build/release/deskdash snapshot --demo --out snapshots` writes `snapshots/*.png` at 1280×720, with sample sessions, purifier readings, weather, load, and track instead of this Mac's own (without `--demo` it draws the real ones). Open the PNGs and look at them after any visual change. That is the test.
- See the Settings window: `.build/release/deskdash snapshot settings --out snapshots` writes `snapshots/settings-<tab>.png`, plus `settings-<tab>-end.png` for a tab taller than the window, scrolled to its end, and `settings-purifier-account.png` for the Purifier tab's Dyson account route. It draws in a window that is never shown, so it needs no running service and takes no focus. The glass tab bar's labels come out blank (the window server draws them). Look at them after any change to Settings.
- Live window: `.build/release/deskdash ctl capture /absolute/path.png` saves what the running service shows.
- Token counts: `.build/release/deskdash tokens` prints each day's tokens as the tokens page counts them, and `--watch` prints today's each time it grows. Try changes on made-up logs: `tokens.claude`, `tokens.codex`, `tokens.gemini`, `tokens.muse` and `tokens.history` in a scratch config point it at them, and `TZ=` moves the day boundaries.
- Now playing without music: `swift scripts/fake-track.swift spotify` (or `music`, then `paused` or `stopped`) posts what the player would announce, and `.build/release/deskdash music` prints what deskdash makes of it. The live service hears the same announcement, so a made-up track stays on the dock screen until you post `stopped`.
- Service: `scripts/install-service.sh` installs the LaunchAgent `local.deskdash`. After a build, `launchctl kickstart -k gui/$(id -u)/local.deskdash` restarts it, and its log is `~/Library/Logs/deskdash.log`. A machine may run deskdash under another label instead (`launchctl list | grep deskdash`); `CLAUDE.local.md` says so. For network trouble, read `/usr/bin/log show --predicate 'process == "deskdash"'` (the full path: zsh has a `log` builtin), and look for "Local network prohibited".
- The README's pictures: `docs/*.png` are demo renders with a config of defaults only, and in UTC, so nothing of this Mac shows, its time zone included. Render `agents` with `TZ=UTC .build/release/deskdash snapshot --demo --config "$(mktemp -u)" --out DIR agents`, the other five with `TZ=UTC .build/release/deskdash snapshot --demo --no-agents --config "$(mktemp -u)" --out DIR clock music climate markets tokens` (no alert frame), then copy them in, `markets-1.png` as `markets.png`.

## Layout

- `Sources/VirtualDisplay/`: an Objective-C wrapper (`DDVirtualDisplay`) for CoreGraphics' private `CGVirtualDisplay`, used only with `display.virtualMain` on. `DDC.swift`: the dock screen's panel power over DDC/CI through IOKit's private IOAVService, used only when the screen goes black with `display.powerOff` on. These are the only private APIs; each degrades to doing nothing. `Displays.swift` (`DisplayManager`) decides when to add or remove it and moves the main display off the dock screen (`display.keepOffMain`, public API).
- `Sources/deskdash/DeskDash.swift`: entry point, CLI parsing, `ctl` (a distributed notification, not a socket).
- `AppDelegate.swift`: the borderless panel on the matching screen, its stacking (above or behind other windows), the right-click menu, Quit (which also unloads the LaunchAgent running it), screen hot-plug, the display-sleep assertion, the 1 s tick, config reload, snapshot rendering.
- `Screens.swift`: which other apps' windows are on a display (`WindowScan`), also behind `deskdash windows`.
- `Dashboard.swift`: the observable model, page rotation, and alert jumps.
- `Markets.swift` (Hyperliquid WebSocket + candles), `Weather.swift` (Open-Meteo, for the place chosen in Settings), `Agents.swift` (Claude registry and hook files): each service writes into `Dashboard` on the main actor.
- `Tokens.swift`: the tokens page's numbers. `TokenScanner` reads the logs of Claude Code, Codex, Gemini CLI and Muse Code where each agent writes them, from where it stopped last time (Gemini's sessions whole, since it writes them over), and counts each reply once, by id. It keeps each day's totals in `tokens.history`, since Claude Code deletes transcripts after 30 days. `TokensService` runs it on the tick: every 10 s while the page shows, every 5 min otherwise. `LocalDay` is a calendar day as a plain number.
- `Limits.swift`: the limits page's numbers. `LimitsReader` reads Claude's from the file `hooks/claude-statusline.sh` writes and Codex's from the tail of its newest session log; `LimitsService` runs it every 5 s and raises the low-limit alert. `UsageWindow` is one window: what is used, when it resets, the even pace, when it runs out.
- `Sound.swift` (`Chime`: the alert sounds and their backing-off repeats; `Notifier`: the notification through osascript; `SystemAudio`: whether the Mac is muted). The alert card is `Dashboard.card`, drawn by `AlertBanner` while the dashboard covers the dock screen, and by `Callout.swift` (a floating panel at the dock screen's top right) while windows keep the dashboard behind them. `Dashboard.alert` raises the sound and the card.
- `L10n.swift`: the menus' and alerts' words in English and Traditional Chinese (`language`). Wrap new menu titles and alert text in `L10n.t`, and add the Chinese to its table.
- `PhotoLibrary.swift`: the Photos app's albums, through PhotoKit, for `photos.album`. Only deskdash.app asks for the library; snapshots and other bare-binary commands never touch it.
- `Photos.swift`: the photos page's pictures. `PhotosService` lists `photos.album` or `photos.folder` every 5 minutes and decodes the next picture (and its blurred backdrop) off the main thread while the page is away.
- `SystemStats.swift`: CPU, temperature, memory, SSD, and network for the clock page, sampled on every other tick (`SystemStatsService.sample`), the volumes Finder shows (`VolumeUsage`, read once a minute and on mount or eject), with disk throughput, swap and the load average for the system page, the last 10 minutes of them (`SystemHistory`), and, only while that page shows, the busiest processes (`ProcessSampler`, libproc). `CPUTemperature` reads the CPU cores' sensors from the SMC.
- `NowPlaying.swift`: Music's and Spotify's distributed notifications (`NowPlayingService`, published on the tick by `flush`), the playhead estimate, and cover lookups (`CoverLookup`). `deskdash music` prints what it hears. `scripts/fake-track.swift` posts a made-up announcement.
- `Views.swift`: everything drawn, on a fixed 1280×720 canvas scaled to the window.
- `MQTT.swift` (a minimal MQTT 3.1 client), `Dyson.swift` (the purifier service and its readings), `DysonSetup.swift` (connecting the purifier: the steps Settings → Purifier and `deskdash dyson setup | test` share, including the one-time Dyson cloud login).
- `Telegram.swift`: watches public channels through their `t.me/s/<name>` preview and hands new posts to `Dashboard.notify`, which shows each one as a `TelegramCard` for `telegram.seconds`.
- `Settings.swift`: the Settings window (`SettingsModel` holds its state; `PurifierSetup` the Purifier tab's setup steps). `AppDelegate` owns the menu bar icon and shared menu, and saves through `ConfigStore.save`, which writes only what differs from the defaults. The window is a `SettingsPanel`, a non-activating panel: since macOS 14 `NSApp.activate()` is only a request the system may refuse, and the panel comes to the front with the keyboard either way. Keep it one.
- `hooks/agent-status.sh`: Codex lifecycle hook, installed by `scripts/install-codex-hooks.sh`. `hooks/claude-statusline.sh`: Claude Code's status line, which copies the plan's limits for the limits page, installed by `scripts/install-claude-statusline.sh`. `hooks/claude-usage.sh`: the same file from the Claude desktop app's `get_usage` JSON, for Claude Code in the app. `scripts/install-service.sh`: the LaunchAgent.

## Rules

- No dependencies beyond the macOS SDK, and no listening ports. It is an appliance; keep it small.
- Nothing personal in the repository. Defaults stay neutral: no place, common tickers, no channels. Anything personal is set in Settings and lives in the gitignored `config.json` and `secrets/`. Sample data (demo sessions, tracks, readings) is made up. Docs pictures come from demo renders, never from a live screen.
- Never trap a window. The panel may sit above other windows (level `.statusBar`) only on a non-main display with no other app's window on it (`updateStacking`, checked every second). Otherwise it stays at desktop level. There must always be a way out that needs no terminal: right-click → Hide or Quit. Quit unloads the LaunchAgent running it (found by `XPC_SERVICE_NAME`), because launchd's KeepAlive restarts a plain exit. This rule exists because a main-display change once moved every window onto the dock screen, underneath the dashboard.
- Design for distance: 1 pt is about 0.09 mm on this panel. Primary text is 60 pt or larger, and meaning is carried by color as well as text. Keep the bottom 60 pt of every page clear for the agent bars.
- No `@State` (or other SwiftUI macros such as `@Entry` and `@Previewable`). In this SDK they are macros, and the Command Line Tools ship no SwiftUI macro plugin, so they fail to compile ("plugin for module 'SwiftUIMacros' not found"). Keep view state in an `@Observable` class; the Observation macros ship with the toolchain. `@Binding` and `@Environment` still work.
- Keep it cheap to run: no continuous animation. A smooth pulse measured 2 to 5% of a core, in the app with SwiftUI or in the window server with Core Animation. Alerts blink on the 1 s tick instead, and data reaches the view at most once a second. Measure before and after with `ps -o time=` on `deskdash` and `WindowServer` over 60 s.
- Never read `~/.claude/sessions/*.key` (session messaging tokens). Only `<pid>.json` is read.
- The agents' transcripts hold whole conversations. Token counting decodes only the lines that carry token counts, and keeps only the counts and times: never store, log, or show anything else from them. The logs are only read, never written.
- Keep token scans cheap. The first pass reads everything in reach. After that a scan reads only appended bytes, and between the 5-minute thorough passes it lists only folders that gained a file and looks only at logs written in the last day: about 1 ms on 2,400 logs, where listing them all took 10. Check the cost on a big made-up history with `deskdash tokens --watch` and `ps -o time=`.
- Now playing listens only to the players' own distributed notifications. No AppleScript: it triggers macOS Automation permission prompts. No MediaRemote: it's private, and macOS restricts it. Never poll the players.
- System stats come from the kernel on the tick. Anything slow goes off the main thread on a slow cadence: the SSD's free-space query goes through CacheDelete (6 to 40 ms), so it runs once a minute, and the temperature waits 3 to 6 ms on the SMC, so it runs every 5 s. The SMC is only ever read: never write a key, since its keys also set the fans and power limits.
- The Dyson connection is read-only: never send `STATE-SET`. `secrets/dyson.json` holds a device credential; never print it, log it, or commit it. Connecting the purifier (Settings → Purifier, or `deskdash dyson setup`) asks a person for secrets; an agent does not run it or type into it. A password is cleared once used and never saved or logged. Test protocol and setup changes against a fake broker first, with a scratch credentials path in the config. `dyson test --host 127.0.0.1:PORT --config FILE` points at one.
- `config.json` is gitignored (personal settings). New settings go in `Config.swift` with a neutral default, and are documented in `config.example.json`; `deskdash config --config config.example.json` prints `{}` while the two agree.
